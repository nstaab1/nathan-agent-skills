One fix from lesson 6 first

You called a test with no assertion a dead test. The difference is whether the test runs.

KindDoes it run?Does it check anything?
DeadNo. It is skipped or disabled.It can't, because it never runs.
TautologicalYes, on every build.No. It passes even when the behaviour is broken.

A test with no assertion runs every time and can never fail, so it is tautological.

The piece we haven't covered: the run-time review

A run-time review is a scheduled look at CI history that files suggestions for shortening runs. Once a week an agent reads the last 30 days of runs, up to 200, and looks for:

It looks atA typical suggestion
Slowest jobs and steps"Install takes four minutes on every run. Cache it."
Jobs that wait for each other"Lint and tests could run side by side."
Jobs that run when they can't be affected"A docs-only change still runs the full suite."
Slowest individual tests"These 40 tests take half the time. Audit them."
How often runs are retried, and time spent queuing"A fifth of runs needed a rerun last week."

It files one ticket per review, ranked by minutes saved per week and linked to the previous review, so you can see whether things are improving. It uses the terms from lesson 1: runs, jobs and steps.

The file that ties it together

docs/agents/ci.md lives in each repo that uses the skills. It is the "standard place to look" you asked for at the start. It records the CI provider, how to fetch run history, the test command, the "rerun only the failures" command if the framework has one, where the verdict script is, the label names, the quarantine cap and which scheduled agents are set up.
