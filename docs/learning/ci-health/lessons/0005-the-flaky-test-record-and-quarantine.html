The flaky-test record and quarantine

In lesson 4 the verdict script did two things with the tracker: it recorded flake occurrences, and it asked which tests were quarantined. This lesson follows one test through that tracker from its first flake to its fix.

What you'll be able to do: look at a test's history and say whether it should be quarantined, who acts next, and how it gets out.

The flaky-test record

A flaky-test record is one ticket in the issue tracker for one flaky test. The verdict script creates it the first time the test flakes.

Part of the ticketWhat it holds
TitleThe test identity from lesson 2: flaky: tests.test_cart test_checkout_total
Labelsflaky-test and ready-for-agent. Later, perhaps quarantined.
CommentsOne per flake occurrence: the date, the branch, the job and a link to the run.

Labels are short tags on a ticket that people and scripts can filter by (GitHub docs on labels). The design uses them as switches. Nothing in the test's code changes at any point.

The quarantine rule

Quarantine means the test still runs but cannot fail the build. On the third occurrence the verdict script adds the quarantined label, but only when all of these hold:

ConditionWhat it protects against
Three flake occurrencesA single blip, such as one slow machine.
All within 30 daysThree flakes spread over two years, which is not a pattern.
Across at least two branchesOne pull request whose own change made the test unreliable. That is the PR's bug.
Under the cap, 5% of the suite by defaultA bad week quietly switching off a large part of your tests.

Who acts, and how it ends

The scheduled agent wakes on a timer and looks at open flaky-test records, quarantined ones first. It opens at most three fix pull requests per run. Each must show the test passing 20 times in a row. The agent never merges. You review and merge.

EndingWhat happens
FixedMerging the fix closes the record, which ends quarantine.
Agent can't fix itIt writes up what it found and relabels the record ready-for-human.
Still not fixed near day 30Seven days before expiry the record goes to a human. At day 30 the label comes off and the test can fail builds again.
Fixed, then flakes again laterThe old record reopens with its history. Occurrences from before the fix don't count toward the new three.
