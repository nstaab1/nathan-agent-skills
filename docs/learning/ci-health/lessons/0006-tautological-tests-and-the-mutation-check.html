Tautological tests and the mutation check

Lessons 1 to 5 covered flaky tests. This one covers the other half of your design, the test audit, which finds tests that cost CI time and protect nothing.

What you'll be able to do: look at a test and name which of the five kinds of unneeded test it is, and say how the audit proves a tautological one.

The test from your baseline

Before lesson 1 I showed you this and asked what was wrong with it:

def test_discount():
    cart = Mock()
    cart.total.return_value = 90
    assert cart.total() == 90

A mock is a stand-in object. It has no behaviour of its own and gives back whatever you tell it to. Read the test with that in mind:

LineWhat it does
cart = Mock()Makes a stand-in cart. The real cart is never created.
cart.total.return_value = 90Tells the stand-in: "when asked for the total, say 90".
assert cart.total() == 90Asks the stand-in for the total and checks it said 90.

Your glossary calls this a tautological test: a test that still passes when the behaviour it claims to verify is broken.

Proving it: the mutation check

"Looks tautological" is an opinion. In Q4 you asked for proof. The mutation check is the proof: break the real code on purpose, run the suspect test, and see what happens.

The idea comes from mutation testing, where a tool makes small deliberate breakages and checks whether any test notices. A breakage no test catches is said to be "alive" (Google Testing Blog, April 2021; Practical Mutation Testing at Scale). Full mutation testing breaks code everywhere and is slow. Your design uses the same trick on one suspect test at a time.

For contrast, here is a version that would fail the moment the discount broke, because it runs the real cart:

def test_discount():
    cart = Cart(items=[Item(price=100)])
    cart.apply_discount(percent=10)
    assert cart.total() == 90

The five kinds of unneeded test

An unneeded test is one whose removal or relocation would lose no verification of behaviour. The audit sorts every finding into one of five kinds.

KindWhat it isExample
TautologicalStill passes when the behaviour is broken.The mock test above.
RedundantChecks a behaviour another test already checks the same way.Two tests that both add a 10% discount and expect 90.
Implementation-coupledFails when code is tidied up with no change in behaviour.A test that insists a private helper was called exactly once.
MisplacedChecks at an expensive level what a cheap level already covers.Starting a browser to check discount arithmetic.
DeadSkipped or disabled with no ticket tracking its return.A test marked "skip" eight months ago.

What the audit does with a finding

KindEvidenceTicket label
TautologicalA mutation checkready-for-agent
DeadThe skip marker itselfready-for-agent
Redundant, implementation-coupled, misplacedWritten reasoningneeds-triage, so you confirm first

The audit only files tickets. It never deletes a test in the same run that judged it. The review skill, ns-code-review, uses the same five kinds to flag unneeded tests in a diff before they are merged.
