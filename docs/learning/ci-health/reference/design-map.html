Design map

The decisions behind the CI-health skills, grouped by skill. The full write-up is spec #12, and the work is split into tickets #13 to #25.

ns-code-review

DecisionTicket
An owned skill named ns-code-review, with no version in the name.#14
The vendored code-review is restored to the vendor's verbatim text.#14
Owned and already-modified skills point at ns-code-review. The verbatim vendor skills tdd and implement are not edited.#14
It carries a short copy of the five kinds of unneeded test and reports them as Standards findings.#16

auditing-tests

DecisionTicket
Five kinds of unneeded test: tautological, redundant, implementation-coupled, misplaced, dead.#15
Tautological findings need a mutation check. Dead tests are shown by their skip marker. The other three rest on written reasoning.#15
The audit files tickets and never deletes tests itself.#15
Tautological and dead go to ready-for-agent. The other three go to needs-triage.#15
It covers a named scope, or the slowest tests first.#15
It runs on demand only, and skips tests with an open flaky-test record.#15

fixing-flaky-tests

DecisionTicket
A flaky test both failed and passed on the same commit. Failing every attempt is a real failure and never counts.#18
Before building, real JUnit XML from pytest and Vitest is inspected, since the retry claims rest on third-party reports.#17
One single-file Node script, the verdict script, copied into each repo with a version line.#18, #23
It wraps the test command, so it sees the real exit code.#18
It does the retry itself and compares two results files. It reruns only the failures when the repo has a command for that, and the whole command otherwise.#18
A crashed or incomplete rerun fails the build. A missing result is never a pass.#18
One flaky-test record per test case, titled with classname plus name, labelled ready-for-agent.#19
Several jobs of one run count as one occurrence. A fixed test that flakes again reopens its old record.#19
Quarantine is a tracker label, with no change to test code (ADR 0001).#20
Into quarantine: three occurrences, within 30 days, across at least two branches, under a cap of 5% of the suite.#20
Tracker unreachable means nothing is treated as quarantined.#20
GitHub and GitLab trackers. Fork pull requests get a verdict but can't record.#19, #21
Setup is delivered as a PR, and the skill warns when scheduled agents aren't documented.#23
The scheduled agent takes quarantined records first, opens at most three fix PRs per run with 20 passes in a row as proof, and never merges.#24
Out of quarantine: the fix is merged, or 30 days pass. A human is warned seven days before.#24
A flaky test may be deleted only when it is one of the five unneeded kinds.#24
Detection from manual job re-runs is not in the first version.spec

reviewing-ci-run-times

DecisionTicket
A weekly scheduled agent, also runnable by hand. Not a job on every run.#25
Reads the last 30 days of runs, up to 200.#25
Checks slow jobs and steps, caching, parallel jobs, sharding, path filters, slow tests, rerun rate and queue time.#25
One ticket per review, ranked by minutes saved per week, linked to the previous review.#25
Slow tests are handed to the audit as a suggested scope.#25

Shared
