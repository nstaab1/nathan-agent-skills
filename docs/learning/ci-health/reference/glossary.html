Glossary

Terms are added as each lesson teaches them. The design's own terms come from GLOSSARY.md in the skills repo and are used here unchanged.

How CI is put together

TermMeaningLesson
RunOne execution of the CI pipeline for one commit. It holds one or more jobs.1
JobA list of steps that execute in order on one runner. Jobs in a run execute side by side unless told otherwise.1
StepOne command inside a job, such as "install" or "run the tests".1
RunnerThe fresh machine that executes one job. It starts with a copy of the repo and nothing else.1
Exit codeThe number a command hands back when it finishes. 0 means success. Anything else means failure.1

JUnit XML

TermMeaningLesson
JUnit XMLA results file layout that nearly every test framework can write. A convention, with no official standard.2
testcaseThe element for one test. Empty means passed.2
failureInside a testcase: an assertion was wrong.2
errorInside a testcase: the test broke before it could finish.2
skippedInside a testcase: the test did not run.2
Test identityclassname plus name, copied exactly from the file. It titles the flaky-test record.2

Retries and flakes

TermMeaningLesson
RetryRunning a failed test again on the same commit.3
Flaky testA test that both failed and passed on the same commit with no code change.3
Flake occurrenceOne CI run in which a test failed and then passed. Failing every attempt is a real failure and never counts.3

The record and quarantine

TermMeaningLesson
Flaky-test recordThe tracker ticket for one flaky test. Its title is the test identity and each comment is a flake occurrence.5
QuarantineThe test still runs but cannot fail the build. It is a label on the record.5
Into quarantineThree flake occurrences, within 30 days, across at least two branches, and under the cap (5% of the suite by default).5
Out of quarantineThe fix is merged and the record closes, or 30 days pass and the label comes off.5
Scheduled agentWakes on a timer, takes quarantined records first, opens at most three fix PRs per run with 20 passes in a row as proof, and never merges.5

Rules worth keeping

RuleWhy it matters to the design
A step fails when its command exits non-zero.This is the only lever the verdict script has for failing a build.
A failed step fails its job, and later steps are skipped.The verdict script must be the thing that runs the tests, or it may never get a turn.
command || true always exits 0.It hides a crash, which is why the design wraps the test command instead.
